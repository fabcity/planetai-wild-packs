# Surf wild pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A wild pack that, at 17:00 the evening before, sends the keeper up to three Bali spots where surf could be good, with every number and a Windy link, takes their `/act` answer, and keeps a per-spot journal.

**Architecture:** One small core change in planetai-node lets a rule message print its own `/act <id>`. The pack does all its judging in a pure-Python module (`surf.py`), the adapter only fetches and stores, the rule's SQL only picks the top three spots and joins lines the adapter already wrote into each sensor's `meta`, and a `review` script builds the journal from the node's alerts and actions plus Open-Meteo's archive.

**Tech Stack:** Python 3 standard library (pack code runs in the node's app container; `hc` is the node's httpx client), PyYAML, duckdb for the rule test, PostgreSQL rule SQL that also runs in duckdb.

**Spec:** `docs/superpowers/specs/2026-11-02-surf-pack-design.md` (this repo, branch `surf-spec-2026-11-02`). Read it first; this plan argues from it.

## Global Constraints

- Pack id and folder: `surf`. Rules are namespaced by folder, so the rule's alerts carry `rule_id = 'surf/surf_tomorrow'`.
- Standard library only in pack code. No `pip:` line. Tests use only the standard library, PyYAML and duckdb, and run from a node folder: `python3 packs/surf/tests/test_x.py`.
- `kind: code`. Loads only with `PACKS_ALLOW_CODE=1`. `requires: { node: ">=<release carrying Task 1>" }` (v0.90.0 is the latest tag; use the next release's number once Task 1 is in it, `>=0.91.0` until then).
- Data: swell from `https://marine-api.open-meteo.com/v1/marine` with `models=ncep_gfswave016`; tide `sea_level_height_msl` from the same endpoint, default model; wind `wind_speed_10m`, `wind_direction_10m`, `wind_gusts_10m` from `https://api.open-meteo.com/v1/forecast`. One multi-location request each. `timezone=auto`, `forecast_days=3`.
- Attribution: "Weather and marine data by Open-Meteo.com (CC BY 4.0); NOAA GFS Wave; Copernicus Marine / MeteoFrance".
- Fetch at most every 3 hours, gated by a stamp file `surf.stamp` in `PACK_OUT` (default `/app/out`), written on every attempt, success or failure.
- Settings: `SURF_SPOTS=` (comma-separated ids; blank = idle, no network) and `SURF_MIN_PERIOD=10`.
- Power: `P = 1025 · 9.81² / (64π) · H² · T / 1000` kW/m (≈ 0.4906 · H² · T).
- Hour gates (spec §5): swell in window, period ≥ min, power in the spot's range; wind offshore ≤ 25 km/h, or < 8 km/h from anywhere; tide third accepted; `wind_wave_height` < half the chosen swell's height. Good = ≥ 2 passing hours in a row between 05:00 and 18:00 local tomorrow; the window is the longest run.
- Mixed: both swells in window, both ≥ min period, weaker ≥ ¼ of the stronger's power, directions ≥ 20° apart. A flag, never a gate.
- Rule: `level: warn`, `cooldown_minutes: 720`, fires only when the local hour is 17, uses only rows written today.
- Message ends with `{act}`; channels all `role: derived`, `comparable: false`; sensors `kind: model`, `scale: bioregion`, `local: false`.
- Every label and message in en, es and id.
- Public text (README, PR body, packs.json `reads`) goes through `anthropic-skills:avoid-ai-writing` in Tomas's voice, twice, before it is pushed.
- Node #1 runs every change before merge (CI green → node #1 on the branch → a real cycle → `tested: node 1` → merge on Tomas's word). Claim node #1 in `~/Obsidian/Hermes/coordination/planetai/STATE.md` first.

## Review Focus

- **A null in Open-Meteo's arrays** (GFS gaps, a secondary swell of `null`): that hour fails its gates, nothing raises. Test in Task 2.
- **Open-Meteo answers 429 or 5xx**: the adapter raises (the node logs it) and the stamp is already written, so the next try is 3 hours later, not every 5-minute poll. Test in Task 3.
- **`SURF_SPOTS` names an id not in `spots.yml`**: it is skipped with one log warning, the others run. Test in Task 3.
- **A flat sea-level day or a missing sea level**: no division by zero; a day with no range counts every hour as `mid`, a missing value fails the tide gate. Test in Task 2.
- **The node was down all day**: at 17:00 the newest rows are yesterday's, and the rule sends nothing. Test in Task 4.

**Interfaces (all in `surf.py`):**
- `KW_PER: float` — `1025 * 9.81**2 / (64 * math.pi) / 1000`
- `power(h: float, t: float) -> float`
- `load_spots(path: str | Path) -> dict[str, dict]` — id → `{"id","name","lat","lon","swell":(lo,hi),"offshore":(lo,hi),"kw":(lo,hi),"tide":set[str],"aliases":list[str]}`
- `within(deg: float, arc: tuple[float, float]) -> bool` — inclusive; wraps when `lo > hi`
- `tide_class(level: float | None, lo: float, hi: float) -> str | None` — thirds; `hi == lo` → `"mid"`; `None` level → `None`
- `day_rows(swell: dict, tide: dict, wind: dict, date: str) -> list[dict]` — one location's three Open-Meteo responses → the 24 hours of `date` (`YYYY-MM-DD`, local) as `{"hr","h1","t1","d1","h2","t2","d2","ww","wind","wdir","sea"}`; missing values stay `None`
- `assess(spot: dict, rows: list[dict], min_period: float = 10.0) -> dict` — `{"good": bool, "from_h": int|None, "to_h": int|None, "swell": {"h","t","dir","kw"}|None, "second": {...}|None, "kw": float, "wind": float|None, "wdir": float|None, "tide": "low"|"mid"|"high"|None}`; `swell`, `second`, `wind`, `tide` describe the window's first hour; `kw` is the mean over the window (0 when not good)
- `line(spot: dict, a: dict, locale: str) -> str` — e.g. `• Uluwatu 5–12: 1.5 m at 12 s from the SSW, 14 kW/m, wind 4 km/h E (offshore), low tide → https://www.windy.com/-8.815/115.087?swell1,-8.815,115.087,12`; `mixed with 0.9 m at 15 s from the SW` inserted after the kW/m when `second`; compass to 16 points; es and id wordings with the same numbers
